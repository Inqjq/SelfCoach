# SelfCoach 需求文档（PRD）

- 版本：v0.1
- 日期：2026-09-08
- 作者：QJQ
- 状态：草案

## 1. 项目概述

### 1.1 背景
作者是一名 Java 后端方向的求职者，计划通过一个「贴近生活、自己会真实使用」的 AI Agent 项目，证明在 RAG / Agent / 记忆 / 安全 / 评估等方面的工程能力，用于简历与面试。项目同时满足个人真实的「自律 + 健身」场景，保证有真实用户（自己）和真实长期数据。

### 1.2 定位（一句话）
一个用自然语言交互的「个人 AI 自律健身教练」：记录训练 / 饮食 / 体重 → 制定与动态调整计划 → 打卡复盘 → 用长期记忆越用越懂你。

### 1.3 目标
1. 可长期日常使用的产品（不是一次性 demo）。
2. 覆盖 RAG、Agent、记忆、安全护栏、可观测 / 评估五大能力。
3. 有可量化指标，能写进简历。

## 2. 目标用户
- 首要用户：作者本人。
- 潜在扩展：有减脂 / 增肌 / 保持健康需求、需要自律监督的普通用户（多用户留到 P2）。

## 3. 产品边界（控制域）★
- ✅ 覆盖：训练计划、动作 / 营养 / 恢复知识、打卡习惯、进度追踪。
- ❌ 不覆盖：医疗诊断、伤病治疗建议、极端 / 危险饮食与训练建议。
- 处理方式：命中禁区时明确拒答，并提示「请咨询医生 / 专业教练」。

> 这个边界是本项目的核心设计决策之一，也是面试亮点：一个专业的健身 agent 必须明确自己的能力范围。

## 4. 核心场景（User Story）
1. 作为用户，我能用文字记录今天的训练（动作 / 重量 / 次数），并随时查询历史。
2. 作为用户，我输入目标（增肌 / 减脂）和每周可用天数，系统生成一份训练计划。
3. 作为用户，我提问「深蹲要不要过脚尖」「这个补剂有用吗」，系统给出带来源引用的回答。
4. 作为用户，我能每天打卡、每周得到复盘报告（练了几次、是否达标、下周怎么调）。
5. 系统能记住我的伤病史、偏好、进步曲线，并在后续计划中自动体现。

## 5. 功能需求（按优先级）

### P0（MVP，第一阶段）
| 编号 | 功能 | 说明 |
|---|---|---|
| F-01 | 训练记录 CRUD | 增删改查训练日志（日期 / 动作 / 重量 / 次数 / 组数） |
| F-02 | 身体指标记录 | 体重 / 围度，形成趋势 |
| F-03 | 知识库问答（RAG） | 健身 / 营养知识问答，返回带来源引用 |
| F-04 | 训练计划生成 | 基于目标 + 可用天数，生成周计划 |
| F-05 | 对话式交互 | CLI / 简单 Web 界面 |

### P1（第二阶段）
- F-06 Agent 工具调用：查询日志、计算配重与渐进超负荷、写入日志、生成周报。
- F-07 长期记忆 / 用户画像：进步曲线、偏好、伤病史。
- F-08 每日打卡 + 周复盘。
- F-09 计划动态调整（根据实际完成情况自动改下周计划）。

### P2（第三阶段）
- F-10 安全护栏（医疗 / 危险内容拒答）。
- F-11 可观测 + 评估体系。
- F-12 多用户 / 登录。
- F-13 图表看板（进度可视化）。

## 6. 非功能需求
| 类别 | 要求 |
|---|---|
| 安全 | 医疗问题拒答并引导就医；身体数据本地化 / 脱敏 |
| 可观测 | 全链路追踪，单次请求的 token 成本、延迟可视化 |
| 评估 | 检索 recall@k、回答正确率、拒答准确率、计划完成率 |
| 可靠性 | 工具调用失败重试；LLM 异常降级；流式输出 |
| 性能 | 知识检索 P95 < 500ms；问答流式返回 |
| 可维护 | 模块化、可测试、文档齐全 |

## 7. 成功指标（量化目标）
- 知识问答引用准确率（答案有据可依）≥ 90%。
- 检索 recall@5 ≥ 85%。
- 医疗 / 危险问题拒答准确率 ≥ 95%。
- 计划生成可用性：作者主观满意。
- 连续使用 ≥ 30 天，积累真实数据。

## 8. 术语表
- RAG：检索增强生成（Retrieval-Augmented Generation）。
- Agent：能自主调用工具完成多步任务的智能体。
- BM25：经典关键词检索算法。
- pgvector：PostgreSQL 的向量扩展。
- rerank：对检索结果做重排序以提升相关性。

## 9. 风险与假设
- 假设：可访问 LLM / Embedding 的 API（OpenAI 兼容接口，国内可用 Qwen / DeepSeek 等）。
- 风险：健身知识库需要可信来源；MVP 期间知识库规模有限，先用公开可信资料。
- 风险：作者需同时准备 Java 求职八股 / 面试，时间与项目需并行管理。
