# SelfCoach 团队分工（多窗口 · 按角色）

> 本项目用一个主仓库 + 多个窗口协作：**一个窗口 = 一个角色 = 一个独立文件夹(clone)**，各角色共享同一个 GitHub 远端，通过分支 + 合并协作。
> 这样每块职责边界清晰、互不干扰，由「架构/主仓」统一把关 main。

## 1. 角色窗口一览

| 角色 | 独立文件夹 | 主要负责 | 工作的分支 |
|---|---|---|---|
| 架构 / 主仓 | `SelfCoach` | 规划路线、维护 main、放行合并、审阅整体 | `main`（+ 合入口） |
| 后端 | `selfcoach-backend` | Java 后端功能（F-01 训练日志 / F-02 身体指标 / F-03 RAG） | `feature/training-log`、`feature/body-metric`、`feature/rag` |
| 前端 | `selfcoach-frontend` | Vue 对话界面（F-05） | `feature/chat-ui` |
| 测试 | `selfcoach-test` | 验证接口、跑验收标准、回归 | `main` 及各 feature 合并后 |
| 代码审查 | `selfcoach-review` | 合并前的代码审查 / PR review | 各 `feature/*` 分支（可灵活使用其他 AI） |

## 2. 分支 → 主要负责角色

| 分支 | 功能 | 主要开发 | 依赖 |
|---|---|---|---|
| `feature/training-log` | F-01 训练日志 CRUD | 后端 | 无（已完成并验证） |
| `feature/body-metric` | F-02 身体指标 | 后端 | 无 |
| `feature/rag` | F-03 知识库问答 | 后端 | 无 |
| `feature/chat-ui` | F-05 对话界面 | 前端 | 依赖后端接口契约 |
| `main` | 稳定主干 | 架构 | — |

> 说明：功能边界 ≠ 角色边界。后端角色一个窗口负责多个后端功能（分别在对应 feature 分支上做）；前端只碰 `chat-ui`。前后端因此能并行。

## 3. 各窗口开工指引

### 架构 / 主仓 窗口
- 只操作 `main`：合并 feature、维护稳定、看全局。
- 合并动作：`git checkout main && git pull && git merge --no-ff feature/xxx && git push origin main`

### 后端窗口（`selfcoach-backend` 文件夹）
- clone 后：`git checkout feature/training-log`（或 body-metric / rag）
- 开发完：`git push origin <当前分支>`
- 提交消息用规范（`feat:` / `fix:` / `docs:` 等）

### 前端窗口（`selfcoach-frontend`）
- clone 后：`git checkout feature/chat-ui`
- 开发 F-05 界面，接口按后端约定（base = `http://<云服务器>:8081/api`，SSE 流式 `/api/chat`）

### 测试窗口（`selfcoach-test`）
- 在合并产物上验证：用 curl / 接口调云服务器 `:8081`
- 对照 `docs/需求文档.md` 的验收标准打勾

### 代码审查窗口（`selfcoach-review`，可换其他 AI）
- 合并前审查：`git diff main...feature/xxx`
- 关注点：分层是否合理、命名、异常处理、是否可讲清每一行

## 4. 协作铁律

1. `main` 始终可跑，禁止直接 push，改动一律走 feature 分支 + 审查后合并。
2. 各自窗口只动自己角色的代码和分支，不跨角色乱改。
3. 谁要合入 main，由架构窗口执行；合并前经代码审查窗口确认。
4. 遇到接口约定问题，后端/前端窗口先对齐契约，再各自实现。
