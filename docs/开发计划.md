# SelfCoach 开发计划（Roadmap）

- 版本：v0.1　|　日期：2026-09-08

## 总览

原则：**MVP 优先，跑通最小闭环 → 逐层叠能力**；核心逻辑尽量手写，基础设施用现成库。每个阶段都有「验收标准」和「简历产出」，保证边做边沉淀。

## Phase 0：项目骨架 + 最小闭环（目标 1 周）

**目标**：把「知识库喂文档 → 提问 → 带引用回答」的 RAG 闭环跑通，同时能记录训练日志。

**任务清单**
1. 搭建 Spring Boot 3 + WebFlux 骨架，配好 pom、docker-compose（PostgreSQL + pgvector）。
2. 建表：`user_profile`、`training_log`、`body_metric`、`doc_chunk`。
3. 训练日志 CRUD 接口（F-01）+ 身体指标记录（F-02）。
4. 知识库入库管线：文档解析、中文分块、Embedding 入库、Lucene 建 BM25 索引。
5. 混合检索 + 融合 + 重排，返回 Top-K。
6. 问答生成：受限回答 + 来源引用（F-03）。
7. 最小交互入口（CLI 或 Thymeleaf 页面，F-05）。

**验收标准**
- 丢入 10 篇健身文档，提问能返回答案并附来源。
- 训练日志能正常增删改查。

**简历产出**：混合检索（BM25 + 向量）、引用溯源、RAG 最小闭环。

## Phase 1：Agent 化（目标 2 周）

**目标**：让系统会「用工具」——查数据、算配重、生成计划、写日志。

**任务清单**
1. 接入 Spring AI，封装统一模型适配层（OpenAI 兼容接口）。
2. 实现工具：查训练日志、写日志、计算配重 / 渐进超负荷、生成周计划、生成周报。
3. 意图分派 + 多步工具编排，失败重试与降级。
4. 计划生成（F-04）与简单的动态调整（F-09 初版）。

**验收标准**
- 说「帮我生成一个每周 4 练的增肌计划」，能产出结构化计划并可选写入日志。
- 说「查我上周训练」，能调工具返回真实数据。

**简历产出**：Agent 工具调用、多步编排、计划生成。

## Phase 2：长期记忆（目标 2 周）

**目标**：做到「越用越懂你」。

**任务清单**
1. 用户画像字段完善（目标、可用天数、伤病史、偏好）。
2. 语义记忆：历史对话向量化存储与召回。
3. 摘要记忆：定期生成进度摘要并注入上下文。
4. 打卡（F-08）+ 周复盘报告。

**验收标准**
- 系统能记住「左膝有旧伤」，后续涉及腿部计划时自动做保护性调整。

**简历产出**：长期记忆 / 用户画像、上下文工程、打卡复盘。

---

## Phase 3：安全 + 评估 + 可观测（目标 2 周）

**目标**：把「专业」两个字做实——有护栏、有指标、有追踪。

**任务清单**
1. 安全护栏：医疗 / 伤病拒答 + 就医引导、危险建议拦截、数据脱敏（F-10）。
2. 接入 Langfuse：全链路追踪 + token 成本 + 延迟（F-11）。
3. 建立 golden 评估集与离线评测脚本：recall@5、回答正确率、拒答准确率。
4. 产品指标统计：计划完成率、连续打卡天数。

**验收标准**
- 问「我膝盖疼怎么办」→ 明确拒答并建议就医。
- Langfuse 能看到每次问答的追踪与成本。

**简历产出**：安全护栏、Langfuse 可观测、评估体系、量化指标。

---

## Phase 4：打磨上线（目标 1-2 周）

**目标**：从「能跑」到「能给人看」。

**任务清单**
1. 多用户 / 登录（JWT，F-12）。
2. 进度图表看板（F-13，可选）。
3. Docker 一键部署，补 README、架构图、demo 视频。
4. 简历包装：把这个项目写成「亮点 + 量化成果」。

**验收标准**
- 别人能按照 README 一键起服务并跑通 demo。

**简历产出**：完整工程闭环、部署、文档、演示。

## 并行事项（重要）
- **求职主线不能停**：Java 八股（集合 / JVM / 并发 / Spring / MySQL / Redis）+ 手撕算法要持续刷。
- 项目是面试的**区分度**，八股是面试的**地基**，两者并行，时间比例建议 6:4（求职 : 项目）按需调整。
